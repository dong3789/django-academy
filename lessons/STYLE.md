# 레슨 작성 가이드 (STYLE)

독자: Node.js 개발자, **휴대폰으로 읽음**, 목표는 면접·실무 수준.
"빠르게 훑는 치트시트"가 아니라 "한 개념씩 이해시키는 강의"를 쓴다.

## 1. 개념 하나 = 4단 구성

모든 개념 섹션(`###`)은 이 순서를 지킨다.

1. **왜 중요한가 (산문 2~5문장)** — 어떤 문제를 해결하는지,
   모르면 어떤 버그/면접 실수가 나는지 먼저 설명한다.
2. **짧은 Python 예제** — 한 가지 포인트만 보여준다.
3. **JS와 비교** — 같은 일을 JS에서는 어떻게 하는지,
   무엇이 다른지 (짧은 코드 또는 한두 문장).
4. **한 줄 요약** — `> 💡 핵심: ...` 형식.

## 2. 코드 블록 규칙 (모바일)

- 블록 하나는 **최대 ~8줄**. 길어지면 개념을 쪼갠다.
- 한 줄은 **45자 이하**. 넘으면 줄바꿈하거나 변수로 나눈다.
- **트레일링 주석 금지.** 주석은 코드 위 별도 줄에 쓴다.

  ```python
  # 좋음: 주석은 위에
  seen = set()
  ```

- 문법 항목 여러 개를 한 블록에 나열하지 않는다
  (예: `a | b; a & b; a - b; a ^ b` 금지 → 필요하면 나눠서).
- 결과값은 `print(...)` 아래에 `# 출력: ...` 주석 줄로 보인다.
- 언어 태그를 항상 붙인다 (`python`, `javascript`, `bash`, `text`).

## 3. 표

- 표는 3열 이하, 셀은 짧게. 설명이 길면 표 대신 문단.

## 4. 연습문제와 면접 질문

- 문제는 번호 목록 대신 `### 문제 N` 소제목으로 쓴다.
  코드가 필요하면 **목록 안에 들여쓰지 말고** 최상위에 둔다
  (리스트 안 코드 블록은 렌더링이 깨지기 쉽다).
- **모든 문제에 개별 `<details>`** 를 단다: 전체 정답 코드 + 해설.
  "힌트만" 금지.
- 면접 질문도 각각 `<details>` + 모범 답안(구조: 정의 → 원리 → 실무 함의).
- `<details>` 마크다운 렌더링 규칙:

  ```html
  <details>
  <summary>정답 보기</summary>

  (빈 줄 필수) 마크다운 본문...

  </details>
  ```

  `<summary>` 다음과 `</details>` 앞에 **빈 줄**을 둔다.
  `<details>`와 `<summary>`는 각각 줄을 나눈다.

## 5. 문체

- 존댓말, 짧은 문장. 한 문단 = 한 생각.
- 용어는 처음 나올 때 한 번 풀어서 설명한다.
- 깊이는 유지한다: CPython 내부, 복잡도, Django 연결을 빼지 않되
  "왜"를 먼저 말한다.

## 6. 커밋 전 체크

- 코드 블록 45자 초과 줄 없음, 블록당 8줄 내외
- 모든 연습문제/면접 질문에 `<details>` 답 존재
- 브라우저(모바일 폭)에서 렌더링 확인
