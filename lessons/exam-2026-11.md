## Q2. == vs is (코드 · Day 1)

아래 출력은 무엇일까요? `==`와 `is` 차이로 이유를 쓰세요.

```python
x = [1, 2]
y = [1, 2]
z = x
print(x == y, x is y, x is z)
```

<details>
<summary>정답 보기</summary>

```text
True False True
```

**설명:**

- `x == y` → 내용이 같아 `True`
- `x is y` → 서로 **다른 리스트 객체**라 `False`
- `x is z` → 같은 객체를 가리켜 `True`

`is`는 식별성(identity), `==`는 동등성(equality)입니다.
`None` 비교만 `is None`, 값 비교는 `==`를 씁니다.

</details>

## Q4. list vs set 멤버십 (개념 · Day 2)

길이 N인 `list`와 같은 원소의 `set`에서
`x in container`의 **평균** 시간 복잡도는 각각?
존재·중복 검사에 set을 쓰는 이유도 한 줄로 쓰세요.

<details>
<summary>정답 보기</summary>

**답:**

- list: 평균 **O(N)** (앞에서부터 선형 탐색)
- set / dict 키: 평균 **O(1)** (해시 테이블)

**실무:** 루프 안 `x in list`는 O(N²)로 커지기 쉽습니다.
존재·중복 체크는 set(또는 dict)으로 바꿉니다.

</details>

## Q6. MRO와 dataclass (면접 · Day 4–5)

다음 두 가지를 짧게 설명하세요.

1. `super()`는 "부모 클래스"를 부를까요, 아니면 무엇을 부를까요?
2. `@dataclass`가 자동으로 만들어 주는 대표 메서드 둘은?

(보너스) dict/set이 평균 O(1)인 이유를 해시 테이블 한 줄로.

<details>
<summary>정답 보기</summary>

**답:**

1. `super()`는 고정된 부모가 아니라 **MRO에서 내 다음 클래스**에 위임합니다.
   헷갈리면 `ClassName.__mro__`를 출력해 순서를 확인합니다.
2. 대표적으로 `__init__`, `__repr__`, `__eq__` 등입니다.
   (`frozen=True`면 `__hash__`도 가능해집니다.)

**보너스:** 키를 해시 → 버킷 인덱스로 바로 찾아가므로 평균 O(1)입니다.
충돌·부하율이 커지면 느려질 수 있어, 해시 가능(불변) 키만 씁니다.

</details>

## Q7. 제너레이터 (코드 · Day 6)

출력을 예측하세요.

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

g = countdown(3)
print(next(g), next(g))
print(list(g))
```

<details>
<summary>정답 보기</summary>

```text
3 2
[1]
```

**설명:** `yield`는 값을 주고 **멈춘 채** 상태를 유지합니다.
`next` 두 번으로 3, 2를 꺼냈고, 남은 값은 1뿐이라 `list(g)`는 `[1]`입니다.
한 번 소비한 제너레이터는 다시 처음부터 돌지 않습니다.

</details>

## Q8. PRG와 CSRF (개념 · Day 7)

1. POST로 Goal을 저장한 뒤 `render`만 하고 `redirect`를 안 하면,
   사용자가 새로고침할 때 무슨 일이 생기나요? 패턴 이름은?
2. Django 템플릿 폼에 `{% csrf_token %}`이 필요한 이유는?

<details>
<summary>정답 보기</summary>

**답:**

1. 브라우저가 **같은 POST를 다시 보내** Goal이 중복 저장됩니다.
   해결은 **PRG**(Post → Redirect → Get). 저장 후 `redirect`하면
   마지막 요청이 GET이라 새로고침해도 조회만 반복됩니다.
2. CSRF는 **다른 사이트가 내 로그인 쿠키로 요청을 위조**하는 공격입니다.
   토큰으로 "이 폼이 우리 사이트에서 온 것"인지 확인합니다.
   (세션 쿠키 인증 API에서도 브라우저 클라이언트를 쓰면 CSRF를 신경 씁니다.)

</details>

## Q9. 템플릿 autoescape (개념 · Day 8)

사용자가 목표 제목에 `<script>alert(1)</script>`를 넣었습니다.
Django 템플릿에서 `{{ goal.title }}`로 출력하면 기본적으로 안전한가요?
왜 그런가요? `|safe`를 쓰면?

<details>
<summary>정답 보기</summary>

**답:** 기본적으로 **안전합니다.** Django는 변수 출력을 **autoescape**해서
`<` → `&lt;` 등으로 바꿉니다. 스크립트가 실행되지 않습니다.

`|safe`나 `mark_safe`는 이스케이프를 **끄므로**, 신뢰할 수 없는 입력에

</details>

## Q10. IDOR와 운영 설정 (면접 · Day 9–10)

1. 목록에서 남의 Goal 링크를 숨겼는데, URL의 pk만 바꾸면 수정 화면이 열립니다.
   이 구멍 이름과 **서버에서** 막는 방법은?
2. 운영에서 `DEBUG=True`, 약한 `SECRET_KEY`가 위험한 이유를 한 줄씩.

<details>
<summary>정답 보기</summary>

**답:**

1. **IDOR**(Insecure Direct Object Reference).
   화면에서 숨기는 건 보안이 아닙니다.
   조회·수정 쿼리에 **반드시** `owner=request.user`(또는 동등 조건)를 넣고,
   없으면 404로 응답합니다. DRF라면 `get_queryset()`에서 같은 필터를 겁니다.
2. `DEBUG=True`는 예외 트레이스·설정 힌트를 노출합니다.
   `SECRET_KEY`가 약하거나 공개되면 세션·CSRF·서명 쿠키를 위조당할 수 있습니다.
   WSGI(gunicorn 등) 뒤에 두고 시크릿은 환경 변수로만 주입합니다.

</details>

## Q11. 요청 생명주기 (개념 · Day 11)

브라우저 GET 요청이 Django에 들어오면, 대략 어떤 순서로 처리되나요?
미들웨어·URL·뷰·템플릿 중 핵심 흐름만 적어 보세요.

<details>
<summary>정답 보기</summary>

**답 (요약):**

1. WSGI/ASGI 서버가 요청을 Django로 전달
2. **미들웨어**가 바깥→안 순으로 요청을 가공

</details>

## Q12. 관계와 N+1 (면접 · Day 12)

`Goal`에 태그(M2M), 체크인(FK, Goal→CheckIn)이 있습니다.

1. Goal을 지울 때 체크인을 같이 지우려면 FK의 `on_delete`에 무엇을 쓰나요?
2. 템플릿에서 `goal.checkins.all`을 Goal 목록 루프 안에서 쓰면
   어떤 문제가 생기고, 어떻게 줄이나요?

<details>
<summary>정답 보기</summary>

**답:**

1. **`CASCADE`**. 부모 Goal 삭제 시 자식 CheckIn도 함께 삭제합니다.
   (`PROTECT`는 자식이 있으면 삭제를 막고, `SET_NULL`은 FK를 NULL로 둡니다.)
2. **N+1 문제**: Goal N개마다 체크인 쿼리가 추가로 나갑니다.
   FK/O2O는 `select_related`, 역참조·M2M은 `prefetch_related`로 미리 가져옵니다.

M2M은 중간 테이블이 생기고, 추가 필드가 필요하면 `through` 모델을 둡니다.

</details>

## Q13. expand–contract (개념 · Day 13)

운영 DB에서 NOT NULL 컬럼을 안전하게 바꾸거나 이름을 옮길 때
쓰는 **expand–contract** 전략을 세 단계로 짧게 설명하세요.
데이터 마이그레이션에서 `apps.get_model`을 쓰는 이유도 한 줄.

<details>
<summary>정답 보기</summary>

**답:**

1. **Expand:** 새 컬럼/테이블을 **추가**(기존은 유지, 앱은 둘 다 쓰기)
2. **Migrate data:** 옛 → 새 로 데이터를 채움 (`RunPython` 등)
3. **Contract:** 옛 컬럼을 읽는 코드를 제거한 뒤, 나중에 컬럼 삭제

한 번에 DROP+ADD 하면 배포 중 구버전 앱이 깨질 수 있습니다.

**`apps.get_model`:** 마이그레이션 시점의 **과거 모델 모양**이 필요해서입니다.
`from app.models import ...`는 "오늘 코드"라 나중에 필드가 바뀌면 옛 마이그레이션이 깨집니다.

</details>

## Q14. QuerySet은 게으르다 (코드 · Day 14)

DB 쿼리는 몇 번 나가나요? 이유를 쓰세요.

```python
qs = Goal.objects.filter(owner=me)
qs = qs.filter(done__lt=F("target"))
qs = qs.annotate(n=Count("checkins"))
first = qs.order_by("-id")[0]
```

<details>
<summary>정답 보기</summary>

```text
1번
```

**설명:** QuerySet은 **lazy**입니다. filter·annotate·order_by는 조건을 쌓기만 하고,
`[0]`처럼 값을 꺼낼 때 SQL이 **한 번** 실행됩니다.
`F("target")`은 파이썬 값이 아니라 **DB 컬럼 참조**로 WHERE에 들어갑니다.
`annotate`+`Count`는 Goal마다 체크인 수를 JOIN/서브쿼리로 붙입니다.

</details>

## Q15. FBV vs CBV (개념 · Day 15)

Goals 목록을 FBV 한 함수로 짜도 되고, `ListView` 같은 CBV로도 됩니다.
각각 **언제 쓰기 좋은지** 한 가지씩, 그리고 CBV에서
`as_view` / `dispatch`가 하는 일을 한 줄씩 쓰세요.

<details>
<summary>정답 보기</summary>

**답:**

- **FBV:** 흐름이 한눈에 보여야 할 때, 분기가 특이한 한 엔드포인트.
- **CBV/제네릭:** 목록·상세·생성처럼 **패턴이 반복**될 때.
  Mixin으로 로그인·권한을 끼우기 쉽습니다.

`as_view()`는 클래스 → 호출 가능한 뷰 함수를 만들고,
`dispatch()`가 HTTP 메서드에 맞는 `get`/`post` 등으로 보냅니다.
Mixin 순서는 MRO를 따르므로 왼쪽→오른쪽 순서를 의식합니다.

</details>

## Q17. Form clean 순서 (코드 · Day 17)

ModelForm 검증에서 아래 중 **먼저** 실행되는 순서로 번호를 매기세요.
(같은 단계면 묶어도 됩니다.)

A. 필드별 `clean_<field>()`
B. 폼의 `clean()` (여러 필드 함께)
C. 필드 to_python / 위젯 값 변환·필수 검사
D. (ModelForm) 모델 `full_clean()` 쪽 모델 검증

"달성량 > 목표 금지" 규칙은 어디에 쓰나요?

<details>
<summary>정답 보기</summary>

**답 순서:** **C → A → B → D**

1. 필드 변환·필수 등
2. `clean_<field>()`
3. 폼 `clean()` — **여러 필드를 함께** 보는 규칙

막히면 `ValidationError` 또는 `add_error`를 씁니다.

**3겹 방어:** 폼/시리얼라이저 → 모델 제약 → DB 제약(`CheckConstraint` 등).

</details>

## Q18. 세션 vs JWT · Admin N+1 (면접 · Day 18–19)

1. 브라우저 Goals 웹앱과 모바일 API 클라이언트에
   세션 인증과 JWT를 각각 언제 쓰기 좋은지 비교하세요.
2. Admin 목록에 FK 컬럼을 넣었더니 페이지마다 쿼리가 폭증합니다.
   한 줄 설정으로 줄이는 방법은?

<details>
<summary>정답 보기</summary>

**답:**

1. **세션:** 같은 사이트 브라우저. 서버가 상태를 쥐어 **즉시 로그아웃·강제 만료**가 쉽고,
   CSRF를 함께 지킵니다.
   **JWT(또는 Token):** 모바일·SPA·외부 클라이언트. Authorization 헤더로 두고
   서버 세션 저장소 없이도 동작하지만, **만료 전 폐기**가 어렵습니다
   (블랙리스트·짧은 만료+refresh 등 전략 필요).
   커스텀 User는 프로젝트 초기에 `AbstractUser` 확장이 가장 덜 아픕니다.
2. **`list_select_related = ("owner", ...)`** (또는 `get_queryset`에서 `select_related`).
   Admin도 N+1이 납니다. `raw_id_fields` / `autocomplete_fields`도 대량 FK에 도움이 됩니다.

## Q19. Serializer는 clean()을 안 부른다 (코드 · Day 21)

모델 `clean()`에 "target은 1 이상"을 넣었는데,
DRF API로 `target=0`이 저장됩니다. 출력이 아니라 **원인과 수정**을 쓰세요.
아래 스케치에서 빈칸을 채워도 됩니다.

```python
class GoalSerializer(serializers.ModelSerializer):
    def validate_target(self, value):
        if value < 1:
            raise serializers.ValidationError("...")
        return value
```

<details>
<summary>정답 보기</summary>

**원인:** ModelForm은 `full_clean()`으로 모델 `clean()`을 부르지만,
**DRF Serializer는 모델 `clean()`을 호출하지 않습니다.**

**수정:** Serializer의 `validate_<field>` / `validate`로 옮기거나,
최후 방어로 DB `CheckConstraint`를 둡니다.
중첩 Serializer 쓰기·partial update·Mass Assignment(`fields`/`extra_kwargs` read_only)
도 같이 점검합니다.

</details>

## Q20. ViewSet·인증·보호·버저닝 (면접 · Day 20, 22–25)

다음을 **각각 2~3문장**으로 답하세요.

1. `post_save`에서 메일을 보냈더니 롤백 후에도 메일이 갑니다. 고치는 법은?
2. `ModelViewSet`에서 IDOR를 막으려면 어디에 필터를 두나요? 404 vs 403은?
3. Session / Token / JWT 인증의 차이를 한 줄씩.
4. 권한·Throttle·Pagination을 "해도 돼? / 얼마나? / 얼마나 잘라?"로 매칭하세요.
5. API가 바뀌어도 옛 앱이 안 깨지게 하는 버저닝·OpenAPI 포인트 한 가지.

<details>
<summary>정답 보기</summary>

**답:**

1. `post_save`는 **커밋 전**에 돕니다. `transaction.on_commit(lambda: send...)`
   으로 **커밋 확정 후** 보냅니다. 가능하면 시그널 대신 서비스 함수에서 명시 호출.
2. **`get_queryset()`**에 `owner=self.request.user` 등을 넣습니다.
   목록·상세·수정·삭제가 모두 이 QuerySet을 씁니다.
   존재하지만 남의 것이면 **404**(정보 누출 최소화)를 쓰는 팀이 많고,
   정책에 따라 403도 가능합니다. 중요한 건 권한만 믿지 말고 **쿼리로 걸러**는 것.
3. **Session:** 쿠키+서버 세션. **Token:** DB에 토큰 저장, 헤더로 전달.
   **JWT:** 서명된 클레임, 서버 저장 없이도 검증(폐기는 별도 전략).
4. **권한** = 해도 돼? / **Throttle** = 얼마나 자주? /
   **Pagination** = 한 번에 얼마나 잘라 줄까?
   (Filtering은 "어떤 조건으로 줄일까?")
5. URL·헤더·쿼리 등으로 **버전을 명시**하고, 하위 호환을 깨는 변경은 새 버전으로.
   OpenAPI(drf-spectacular 등)로 스키마를 코드와 함께 배포하면
   클라이언트·문서 불일치를 줄입니다.

</details>
