## 오늘의 비유

함수 호출은 **책상 위에 서류철을 쌓는 것**입니다.
새로 호출하면 서류철을 올리고, 끝나면 맨 위 것을 치웁니다.
그 서류철 안에서 이름(변수)을 찾다가 없으면 바깥 책장으로 갑니다.

## 1. 스코프 — 이름을 어디서 찾나

**JS (Node)**

```javascript
let count = 0;
function inc() {
  count += 1;
}
inc();
console.log(count);
// 1
```

**Python**

```python
count = 0
def inc():
    count += 1
inc()
# UnboundLocalError!
```

똑같아 보이는데 Python은 에러입니다. 이유:
**함수 안에서 대입하는 이름은 그 함수의 로컬**로 결정되기 때문입니다.
`count += 1`이 대입이므로 `count`는 로컬인데, 아직 값이 없죠.

```mermaid
flowchart LR
  L["Local 함수 안"] --> E["Enclosing 바깥 함수"]
  E --> G["Global 모듈"]
  G --> B["Built-in print 등"]
```

이 순서를 **LEGB**라고 부릅니다. 읽기는 이 순서로 찾고,
쓰기(대입)는 기본적으로 Local에만 합니다.

```python
def inc():
    global count
    count += 1
```

> 💡 바깥 변수에 대입하려면 `global`(모듈) / `nonlocal`(바깥 함수).

<details>
<summary>🔍 더 깊이 (면접용): 왜 컴파일 시점에 정해지나</summary>

CPython은 함수를 **바이트코드로 컴파일할 때** 각 이름이
로컬인지 결정합니다. 대입이 함수 어디에든 있으면 로컬입니다.
그래서 대입보다 **앞 줄**에서 읽어도 에러가 납니다.

로컬 변수는 dict가 아니라 프레임의 고정 배열(`LOAD_FAST`)에
저장돼 빠릅니다. `dis.dis(inc)`로 확인할 수 있습니다.

블록(`if`, `for`)은 스코프가 아닙니다. JS의 `let` 블록 스코프가 없어요.
컴프리헨션만 예외로 자기 스코프를 가집니다 (3.x).

실무에서 `global`은 거의 쓰지 않습니다. 상태는 클래스나 인자로 넘기세요.

</details>

## 2. 클로저와 콜 스택

**JS (Node)**

```javascript
function counter() {
  let n = 0;
  return () => ++n;
}
const c = counter();
c(); console.log(c());
// 2
```

**Python**

```python
def counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc
```

같은 개념입니다. 차이는 Python에서 바깥 변수를 바꾸려면 `nonlocal`이
필요하다는 것, 그리고 `lambda`는 **표현식 하나**만 됩니다.

**비유**: 클로저는 **도시락 가방**. 함수가 바깥으로 나갈 때
필요한 변수를 가방에 넣어 들고 갑니다.

호출이 쌓이고 빠지는 모습(콜 스택)은 이렇습니다:

![콜 스택 애니메이션](assets/gif/day3-call-stack.gif)

### 면접 단골 함정: 루프 람다

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])
# 출력: [2, 2, 2]
```

람다는 `i`의 **값이 아니라 이름**을 기억합니다.
호출 시점의 `i`는 마지막 값 2입니다 (late binding).

```python
fs = [lambda i=i: i for i in range(3)]
# 출력: [0, 1, 2]
```

**JS 비교**: JS는 `for (let i...)`가 반복마다 새 `i`를 만들어
이 문제가 없습니다. (`var`였다면 같은 문제!)

> 💡 클로저는 값이 아니라 변수를 잡는다. 지금 값을 고정하려면 기본 인자.

<details>
<summary>🔍 더 깊이 (면접용): cell, 재귀 한도, 데코레이터</summary>

**cell**: 클로저 변수는 `inc.__closure__[0].cell_contents`에 있습니다.
바깥 함수가 끝나도 cell 객체가 살아남아 값을 보관합니다.

**스택 프레임**: 호출마다 로컬 변수·다음 실행 위치를 담은 프레임이 쌓입니다.
Python 재귀 한도는 기본 1000 (`sys.getrecursionlimit()`).
꼬리 호출 최적화(TCO)가 없어서 깊은 재귀는 반복문으로 바꿔야 합니다.

**데코레이터는 클로저**입니다:

```python
def log(fn):
    def wrap(*a, **kw):
        print("call", fn.__name__)
        return fn(*a, **kw)
    return wrap
```

`@log`는 `add = log(add)`와 같습니다. 실무에선 `functools.wraps`를 붙여
원래 이름/문서를 보존합니다. Django의 `@login_required`가 이 구조입니다.

</details>

## 3. 인자: *args, **kwargs, 키워드 인자

**JS (Node)**

```javascript
function boot(name, ...rest) {}
function connect({ host, port = 5432 }) {}
connect({ host: "db" });
```

**Python**

```python
def boot(name, *args, **kwargs):
    print(name, args, kwargs)
boot("app", 1, 2, pid=7)
# 출력: app (1, 2) {'pid': 7}
def connect(host, port=5432): ...
connect(host="db")
```

- `*args` = JS `...rest` (tuple로 받음)
- `**kwargs` = 이름 붙은 나머지 인자 (dict로 받음)
- Python은 **키워드 인자**가 문법에 있어, JS처럼 객체로 감쌀 필요가 없습니다.

```text
boot("app", 1, 2, pid=7)
      │     └┬─┘  └─┬─┘
     name  args   kwargs
```

호출할 때 펼치기(spread)도 됩니다: `f(*lst, **dct)`.

> 💡 `*`는 위치 인자 묶음(tuple), `**`는 이름 인자 묶음(dict).

<details>
<summary>🔍 더 깊이 (면접용): / 와 * 구분자, partial</summary>

```python
def f(a, /, b, *, c):
    ...
f(1, 2, c=3)
f(1, b=2, c=3)
```

- `/` 앞: **위치 전용** (`a=1`로 못 넘김)
- `*` 뒤: **키워드 전용** (`c`는 반드시 이름으로)

키워드 전용은 bool 플래그에 좋습니다: `save(force=True)`가
`save(True)`보다 훨씬 읽기 쉽죠. Django ORM도 많이 씁니다.

`functools.partial(greet, "Hi")`는 인자를 미리 채운 새 함수
(JS의 `fn.bind(null, "Hi")`).

인자 순서 규칙: 위치 → `*args` → 키워드 전용 → `**kwargs`.

</details>

## 연습문제

### 문제 1. make_adder

`make_adder(2)(3) == 5`가 되게 만드세요.

<details>
<summary>정답 보기</summary>

```python
def make_adder(n):
    def add(x):
        return x + n
    return add
```

`n`을 읽기만 하므로 `nonlocal`이 필요 없습니다.

</details>

### 문제 2. sum_all

`sum_all(1, 2, 3, scale=10)` → `60`

<details>
<summary>정답 보기</summary>

```python
def sum_all(*nums, scale=1):
    return sum(nums) * scale
```

`*nums` 뒤의 `scale`은 자동으로 키워드 전용이 됩니다.

</details>

### 문제 3. 에러 이유 설명

```python
total = 0
def add(x):
    print(total)
    total = total + x
```

<details>
<summary>정답 보기</summary>

`add(1)` 호출 시 **첫 줄 `print(total)`에서** `UnboundLocalError`.
함수 안에 `total =` 대입이 있어서 컴파일 시 `total`이 로컬로 정해졌고,
print 시점엔 로컬 값이 아직 없습니다. 해결: `global total` 또는
`return total + x`로 상태를 바깥에서 관리.

</details>

## 면접 질문

<details>
<summary>Q. 클로저의 late binding이란? 어떻게 피하나요?</summary>

- **정의**: 클로저는 변수의 값이 아니라 변수(cell)를 참조합니다.
- **원리**: 루프 변수는 하나의 cell을 공유하므로, 호출 시점의
  마지막 값을 봅니다.
- **해결**: 기본 인자 `lambda i=i: i`, `functools.partial`,
  또는 팩토리 함수로 반복마다 새 스코프를 만듭니다.

</details>

## 오늘 정리

1. 이름 찾기는 LEGB, 대입하면 로컬 → `global`/`nonlocal`.
2. 클로저는 변수를 잡는다 — 루프 람다는 `i=i`로 고정.
3. `*args`=rest(tuple), `**kwargs`=이름 인자(dict).
