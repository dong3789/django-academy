# Day 3 · 함수·스코프·클로저 · *args/**kwargs

> 목표: 함수를 **일급 객체**로 다루고, LEGB·`nonlocal`·클로저·가변 인자 규칙을 면접에서 구조적으로 설명할 수 있다. Node의 클로저·rest 감각을 Python 규칙으로 정확히 옮긴다.

## 1. 함수는 객체다

Python에서 `def`는 문장이지만, 만들어지는 것은 **callable 객체**입니다. 변수에 담고, 인자로 넘기고, 리스트에 넣을 수 있습니다 — JS의 함수와 같은 "일급"입니다.

```javascript
function add(a, b) { return a + b; }
const add2 = (a, b) => a + b;
const ops = [add, add2];
ops[0](1, 2);            // 3
```
```python
def add(a, b):
    return a + b

add2 = lambda a, b: a + b   # 표현식만; 문장(if/for) 불가
ops = [add, add2]
ops[0](1, 2)                # 3
print(add.__name__, add.__code__.co_argcount)  # add 2
```

`return`이 없으면 `None`을 반환합니다. JS처럼 `undefined`가 아닙니다.

```python
def f():
    pass
f() is None   # True
```

## 2. LEGB — 이름 찾는 순서

이름을 보면 인터프리터는 **L → E → G → B** 순으로 찾습니다.

| 단계 | 이름 | 의미 |
|---|---|---|
| L | Local | 현재 함수 본문 |
| E | Enclosing | 바깥 함수(중첩)의 로컬 — 클로저의 free variable |
| G | Global | 모듈 최상위 |
| B | Built-in | `len`, `range` 등 `builtins` |

```python
x = "G"

def outer():
    x = "E"
    def inner():
        # x = "L"   # 주석 해제하면 L
        return x    # E (enclosing)
    return inner

outer()()           # 'E'
```

### `global` / `nonlocal`

대입(`x = ...`)은 **기본으로 로컬 변수 선언**입니다. 바깥을 바꾸려면 명시해야 합니다.

```python
count = 0

def bump_wrong():
    count = count + 1   # UnboundLocalError: 대입 때문에 count가 로컬로 잡힘

def bump():
    global count
    count += 1

def make_counter():
    n = 0
    def inc():
        nonlocal n      # enclosing의 n을 바꿈 (global이 아님!)
        n += 1
        return n
    return inc

c = make_counter()
c(); c()                # 1, 2
```

JS 대비: `let`/`const`는 블록 스코프, `var`는 함수 스코프. Python은 **함수 스코프**(컴프리헨션·제너레이터 표현식은 별도 스코프)이고, 블록(`if`/`for`)은 새 스코프를 만들지 않습니다.

```python
if True:
    y = 10
print(y)                # 10 — if 블록도 모듈/함수 스코프에 남음
```

## 3. 클로저 — free variable이 살아 남는 이유

**클로저** = 함수 객체 + 그 함수가 참조하는 **enclosing 변수(셀)** 묶음.

```python
def make_multiplier(k):
    def mul(x):
        return x * k    # k는 free variable
    return mul

double = make_multiplier(2)
triple = make_multiplier(3)
double(10), triple(10)  # (20, 30)
```

`make_multiplier`가 끝나도 `k`는 스택 프레임과 함께 죽지 않습니다. CPython은 free variable을 **cell 객체**에 넣고, 함수의 `__closure__`가 그 셀을 가리킵니다.

```python
double.__closure__[0].cell_contents   # 2
```

### Late binding 함정 (루프 + 람다)

```python
# 버그 — 세 함수 모두 i의 "최종값"을 본다
fns = [lambda: i for i in range(3)]
[f() for f in fns]      # [2, 2, 2]  (Python 3)

# 수정 1: 기본 인자로 스냅샷
fns = [lambda i=i: i for i in range(3)]
[f() for f in fns]      # [0, 1, 2]

# 수정 2: 팩토리
def make(i):
    return lambda: i
fns = [make(i) for i in range(3)]
```

JS에서도 `var` 루프 + 클로저가 같은 함정이었고, `let`은 이터레이션마다 바인딩이 갈라져 덜 밟습니다. Python 컴프리헨션의 루프 변수는 3.x에서 컴프리헨션 스코프에 있지만, **람다가 닫는 이름은 여전히 late binding**입니다.

## 4. 인자 규칙: positional / keyword / *args / **kwargs

```python
def f(a, b, /, c, d=0, *, e, f=1, **kw):
    ...
# a, b : positional-only (/ 앞) — f(1,2, ...) OK, f(a=1,...) TypeError
# c, d : positional or keyword
# e, f : keyword-only (* 뒤)
# **kw : 나머지 키워드
```

```python
def log(level, *messages, sep=" ", **meta):
    print(f"[{level}]", sep.join(messages), meta)

log("INFO", "boot", "ok", host="local")
# [INFO] boot ok {'host': 'local'}
```

| Python | JS 감각 |
|---|---|
| `*args` (튜플) | rest `...args` (배열) |
| `**kwargs` (dict) | 나머지 프로퍼티 모으기는 객체 스프레드 패턴 |
| `f(*xs, **kw)` 호출 | `f(...xs)` / 객체 스프레드 |
| `/` positional-only | (언어 차원 대응 약함) |
| `*` keyword-only | (명시적 옵션 객체 패턴과 유사) |

```python
xs = [1, 2, 3]
kw = {"e": 9}
# f(0, *xs, **kw) 처럼 언패킹
```

**기본 인자 평가 시점**: 함수 **정의 시 한 번**. mutable default 공유 버그는 Day 1–2와 동일.

```python
def append_to(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

## 5. 고차 함수 · lambda · partial

```python
from functools import partial, wraps

nums = [3, 1, 2]
sorted(nums, key=lambda x: -x)     # [3, 2, 1]

def greet(greeting, name):
    return f"{greeting}, {name}"

hi = partial(greet, "Hi")
hi("dh")                           # 'Hi, dh'
```

데코레이터는 "함수를 받아 함수를 돌려주는 고차 함수"의 문법 설탕입니다(본격은 Day 7 근처). 지금은 형태만:

```python
def trace(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        print("call", fn.__name__, args)
        return fn(*args, **kwargs)
    return wrapper

@trace
def add(a, b):
    return a + b
```

JS: `fn.bind(null, 1)` ≈ `partial(fn, 1)`. 화살표 함수는  Lexical `this` — Python에는 `this`가 없고, 메서드의 `self`는 디스크립터로 바인딩됩니다(Day 4).

## 6. CS 심화: 콜 스택 · 활성화 레코드 · 클로저 셀

### 콜 스택 (call stack)

함수를 호출하면 **스택 프레임(활성화 레코드)** 이 쌓입니다. 대략 포함:

- 복귀 주소 / 이전 프레임 링크
- 지역 변수, 인자
- 평가 중인 연산 임시값

```text
main
 └─ outer()          ← frame: k 등의 로컬
     └─ mul(10)      ← frame: x=10, freevar 셀로 k 참조
```

재귀가 깊어지면 프레임이 계속 push → **스택 오버플로**. CPython은 `sys.getrecursionlimit()`(기본 약 1000)으로 막습니다. JS 엔진도 콜 스택 한도가 있고, 브라우저마다 다릅니다.

```python
import sys
sys.setrecursionlimit(2000)   # 근본 해결은 아님 — 알고리즘을 반복/명시 스택으로
```

### 왜 클로저는 힙인가?

프레임은 함수 return 시 pop됩니다. 그런데 반환된 내부 함수가 enclosing 변수를 계속 쓰면, 그 값을 스택에 둘 수 없습니다. 그래서:

1. free variable을 **cell**로 승격
2. cell은 **힙**에 할당
3. 내부 함수 객체가 cell을 참조 → 참조 카운트가 살아 있는 한 값 유지

면접 한 줄: **"스택 프레임은 사라지지만, 클로저가 붙잡은 셀은 힙에 남아 GC 대상이 된다."**

### 꼬리재귀?

Python은 **꼬리호출 최적화(TCO)를 하지 않습니다**. `return f(...)`여도 프레임이 쌓입니다. 깊은 재귀는 루프나 명시적 스택으로 바꾸세요.

## 7. 흔한 함정

```python
# 1) UnboundLocalError — 대입 때문에 로컬로 잡힘
x = 1
def f():
    print(x)   # 아래에 대입이 있으면 여기도 로컬로 간주 → 에러
    x = 2

# 2) 루프 클로저 late binding (위 참고)

# 3) mutable default
def f(a, cache={}): ...

# 4) *args는 튜플 — 가변 리스트가 필요하면 list(args)

# 5) 키워드 인자를 위치와 섞을 때 순서
def g(a, b, c): ...
g(1, c=3, b=2)   # OK
g(1, b=2, 3)     # SyntaxError: positional after keyword
```

## 8. 연습문제

1. `make_adder(n)`을 클로저로 작성하고, `add5 = make_adder(5); add5(3) == 8`을 확인하라. `__closure__`로 셀 값을 출력하라.
2. 아래를 고쳐 `[0,1,2]`가 나오게 하라.
   ```python
   funcs = []
   for i in range(3):
       funcs.append(lambda: i)
   ```
3. `def f(a, /, b, *, c): ...`에 대해 合法/非法 호출 예를 각각 2개씩 적어라.
4. `sum_all(*nums, start=0)`을 구현하라. `sum_all(1,2,3, start=10) == 16`.
5. (심화) 재귀로 팩토리얼을 짠 뒤, `sys.setrecursionlimit` 없이도 n=2000에서 동작하도록 **반복**으로 바꿔라. 콜 스택 관점에서 왜 안전한지 3줄로 설명하라.

<details><summary>힌트 / 해설</summary>

- 1: `def make_adder(n):\n    def add(x): return x+n\n    return add` → `add5.__closure__[0].cell_contents`
- 2: `lambda i=i: i` 또는 `def make(i): return lambda: i` 후 `make(i)`
- 3: OK 예 `f(1,2,c=3)`, `f(1,b=2,c=3)`. 非法 `f(a=1,b=2,c=3)`(/ 때문에), `f(1,2,3)`(* 때문에 c는 키워드 전용)
- 4: `total = start; for n in nums: total += n; return total` 또는 `return start + sum(nums)`
- 5: 루프 한 프레임만 사용 → 깊이 n과 무관하게 스택 O(1). 재귀는 프레임 n개 → limit에 걸림.
</details>

## 9. 면접 질문

<details><summary>Q1. LEGB와 <code>nonlocal</code>/<code>global</code> 차이를 짧게 설명해 보세요.</summary>

이름은 Local → Enclosing → Global → Built-in 순으로 찾습니다. 대입은 기본적으로 로컬 바인딩을 만듭니다. 모듈 전역을 바꾸려면 `global`, 바로 바깥 함수의 변수를 바꾸려면 `nonlocal`입니다. `nonlocal`은 전역까지 건너뛰지 않습니다.
</details>

<details><summary>Q2. 클로저란 무엇이고, 바깥 함수가 끝난 뒤에도 값이 남는 이유는?</summary>

내부 함수가 enclosing 변수를 참조할 때, 그 함수 객체와 free variable 셀의 묶음이 클로저입니다. 스택 프레임은 return 시 사라지지만 free variable은 힙의 cell로 승격되고, 내부 함수가 셀을 참조하는 한 GC되지 않습니다. CPython에서는 `fn.__closure__`로 셀을 볼 수 있습니다.
</details>

<details><summary>Q3. <code>*args</code>/<code>**kwargs</code>와 JS rest/spread를 비교하고, positional-only(<code>/</code>)를 쓰는 이유를 말해 보세요.</summary>

`*args`는 남는 위치 인자를 튜플로, `**kwargs`는 남는 키워드를 dict로 모읍니다. 호출부 `*seq`/`**map`은 JS spread와 비슷합니다. `/` 앞 인자는 이름 없이만 받게 해 API에서 내부 파라미터 이름을 바꾸어도 키워드 호출 호환성이 깨지지 않게 하고, 위치 의미를 강제합니다(`len(x)`처럼).
</details>
