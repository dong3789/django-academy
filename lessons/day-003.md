## Part 1. 함수는 객체다

### 1-1. 일급 함수

`def`로 만든 함수는 **그냥 객체**입니다. 변수에 담고,
인자로 넘기고, 리스트에 넣을 수 있습니다.
콜백·전략 패턴·데코레이터가 모두 이 성질에 기댑니다.

```python
def add(a, b):
    return a + b

op = add
print(op(1, 2))
# 3
print(add.__name__)
# add
```

**JS에서는:** 완전히 같습니다. 함수가 일급 객체입니다.

> 💡 핵심: 함수도 값이다. 담고, 넘기고, 반환할 수 있다.

### 1-2. lambda는 "표현식 하나"뿐

Python `lambda`는 JS 화살표 함수보다 훨씬 제한적입니다.
**표현식 하나**만 가능하고 `if` 문, `for` 문, 여러 줄을 쓸 수 없습니다.
정렬 키처럼 아주 짧은 곳에만 쓰고, 나머지는 `def`로 이름을 붙입니다.

```python
users = [("b", 30), ("a", 20)]
users.sort(key=lambda u: u[1])
print(users)
# [('a', 20), ('b', 30)]
```

**JS에서는:** `(u) => { ...여러 줄... }`이 자유롭습니다.
Python에선 그 정도면 `def`를 쓰는 게 관용입니다.

> 💡 핵심: lambda는 한 줄 표현식 전용. 길면 def.

### 1-3. return이 없으면 None

`return`을 안 쓰거나 값 없이 `return`하면 `None`이 반환됩니다.
"리스트를 정렬해서 반환하겠지" 하고 `x = lst.sort()`를 쓰면
`x`가 `None`이 되는 실수가 흔합니다.

```python
lst = [3, 1]
x = lst.sort()
print(x)
# None
y = sorted(lst)
```

제자리 변경 메서드(`sort`, `append`)는 `None`을 반환하고,
새 값을 원하면 `sorted()` 같은 함수를 씁니다.

**JS에서는:** `arr.sort()`는 정렬된 **같은 배열**을 반환합니다.

> 💡 핵심: 제자리 변경 메서드는 None을 돌려준다.

## Part 2. 스코프 — 이름을 어디서 찾나

### 2-1. LEGB 규칙

코드에서 이름 `x`를 만나면 Python은 네 곳을 순서대로 찾습니다.
처음 찾은 곳의 값을 씁니다.

1. **L**ocal: 지금 함수 안
2. **E**nclosing: 감싸고 있는 바깥 함수
3. **G**lobal: 모듈 최상위
4. **B**uilt-in: `len`, `print` 같은 내장

```python
x = "G"
def outer():
    x = "E"
    def inner():
        return x
    return inner()
print(outer())
# E
```

`inner` 안에 `x`가 없으니 바깥(E)에서 찾았습니다.

**JS에서는:** 스코프 체인과 같은 개념입니다. 차이는 다음 절.

> 💡 핵심: 이름 찾기 = Local → Enclosing → Global → Built-in.

### 2-2. 대입하면 로컬이 된다 (UnboundLocalError)

Python에서 함수 안 어디서든 `x = ...`로 **대입**하면,
그 함수 전체에서 `x`는 로컬 변수로 취급됩니다.
그래서 대입 **전에** 읽으면, 바깥에 같은 이름이 있어도 에러가 납니다.

```python
count = 0
def bump():
    count = count + 1

bump()
# UnboundLocalError
```

컴파일 시점에 "이 함수에서 count는 로컬"로 결정되기 때문입니다.
`+=`도 대입이므로 똑같습니다.

**JS에서는:** `let count = count + 1`을 함수 안에 쓰면 TDZ로
비슷한 에러가 나지만, 그냥 `count = count + 1`은 바깥 변수를 바꿉니다.

> 💡 핵심: Python은 "대입 = 로컬 선언". 선언 키워드가 없어서 생기는 규칙.

### 2-3. global과 nonlocal

바깥 변수를 **바꾸고** 싶으면 명시해야 합니다.
모듈 변수는 `global`, 감싼 함수의 변수는 `nonlocal`입니다.

```python
def make_counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc
```

```python
c = make_counter()
c()
print(c())
# 2
```

`global`은 테스트와 동시성을 어렵게 하므로 실무에선 거의 안 씁니다.

**JS에서는:** 클로저 변수를 그냥 `n++` 하면 됩니다.
선언 키워드(`let`)가 있어서 이런 키워드가 필요 없습니다.

> 💡 핵심: 읽기는 자유, 바깥 변수 재할당은 `nonlocal`/`global` 필수.

### 2-4. 블록은 스코프가 아니다

`if`, `for`, `with`, `try`는 새 스코프를 만들지 않습니다.
안에서 만든 변수가 블록 밖에서도 보입니다.
(예외: 컴프리헨션은 자체 스코프가 있습니다.)

```python
if True:
    y = 10
print(y)
# 10
```

**JS에서는:** `let`/`const`는 블록 스코프라 `ReferenceError`.
Python은 `var`처럼 **함수 스코프**입니다.

> 💡 핵심: Python 스코프 경계 = 함수, 클래스, 모듈, 컴프리헨션.

## Part 3. 클로저

### 3-1. 클로저란

함수가 **자기 바깥 변수를 기억한 채** 반환되면 클로저입니다.
설정값을 고정한 함수를 찍어내는 "함수 공장"에 쓰고,
데코레이터의 핵심 원리이기도 합니다.

```python
def make_mul(k):
    def mul(x):
        return x * k
    return mul

double = make_mul(2)
print(double(10))
# 20
```

`make_mul`은 이미 끝났는데 `k`가 살아 있습니다.

**JS에서는:** 완전히 같은 개념, 같은 코드 모양입니다.

> 💡 핵심: 클로저 = 함수 + 기억한 바깥 변수.

### 3-2. 값이 어디에 남아 있나: cell

함수가 끝나면 그 스택 프레임은 사라집니다. 그런데 `k`는 어떻게 남았을까요?
CPython은 클로저가 참조하는 변수를 **cell 객체**에 넣어 힙에 둡니다.
내부 함수의 `__closure__`가 그 셀을 가리킵니다.

```python
cell = double.__closure__[0]
print(cell.cell_contents)
# 2
```

함수 객체가 셀을 참조하는 한 셀은 GC되지 않습니다.

> 💡 핵심: 프레임은 사라져도 셀은 힙에 남는다.

### 3-3. Late binding 함정

클로저는 **값이 아니라 변수**를 기억합니다.
그래서 루프에서 람다를 만들면, 나중에 호출할 때의 변수값
(= 루프의 마지막 값)을 보게 됩니다.

```python
fns = [lambda: i for i in range(3)]
print([f() for f in fns])
# [2, 2, 2]
```

해결: 기본 인자는 **정의 시점**에 평가된다는 성질을 이용합니다.

```python
fns = [lambda i=i: i for i in range(3)]
print([f() for f in fns])
# [0, 1, 2]
```

**JS에서는:** `for (let i...)`는 반복마다 새 바인딩이라 괜찮고,
`var`면 같은 함정입니다.

> 💡 핵심: 클로저는 변수를 참조한다. 값을 고정하려면 `i=i`.

## Part 4. 인자 규칙

### 4-1. 위치 인자와 키워드 인자

Python은 호출할 때 **이름을 붙여** 인자를 넘길 수 있습니다.
순서를 외울 필요가 없고, 옵션이 많은 함수가 읽기 쉬워집니다.

```python
def connect(host, port=5432):
    return f"{host}:{port}"

print(connect("db", port=6543))
# db:6543
```

규칙: 위치 인자가 먼저, 키워드 인자가 뒤.
`connect(port=1, "db")`는 `SyntaxError`입니다.

**JS에서는:** 키워드 인자가 없어서 옵션 객체
`connect({host, port})` 패턴을 씁니다.

> 💡 핵심: 키워드 인자 = 언어가 지원하는 옵션 객체.

### 4-2. *args — 나머지 위치 인자

개수가 정해지지 않은 인자를 **튜플**로 모읍니다.

```python
def total(*nums):
    return sum(nums)

print(total(1, 2, 3))
# 6
```

**JS에서는:** `function total(...nums)`. 차이: JS는 배열,
Python은 **튜플**(불변)입니다.

> 💡 핵심: `*args` = rest 파라미터(튜플).

### 4-3. **kwargs — 나머지 키워드 인자

이름 붙은 나머지 인자를 **dict**로 모읍니다.
Django에서 `Model.objects.filter(**conditions)`처럼
조건을 동적으로 만들 때 반대 방향(펼치기)으로 아주 많이 씁니다.

```python
def log(msg, **meta):
    print(msg, meta)

log("boot", host="local", pid=7)
# boot {'host': 'local', 'pid': 7}
```

호출 쪽에서 `*`/`**`를 쓰면 반대로 **펼칩니다**.

```python
args = ["db"]
opts = {"port": 6543}
connect(*args, **opts)
```

**JS에서는:** 펼치기는 `f(...arr)`, 객체는 옵션 객체 spread.

> 💡 핵심: 정의에서 `*`/`**`는 모으기, 호출에서는 펼치기.

### 4-4. / 와 * : 위치 전용, 키워드 전용

인자 목록에 `/`를 넣으면 그 앞은 **이름으로 못 넘기고**,
`*`를 넣으면 그 뒤는 **이름으로만** 넘길 수 있습니다.

```python
def f(a, /, b, *, c):
    return a + b + c

f(1, 2, c=3)
f(1, b=2, c=3)
```

- `f(a=1, ...)` → TypeError (a는 위치 전용)
- `f(1, 2, 3)` → TypeError (c는 키워드 전용)

**왜 쓰나?** 키워드 전용(`*`)은 `sort(key=..., reverse=True)`처럼
"플래그가 뭘 뜻하는지" 호출부에서 보이게 강제합니다.
위치 전용(`/`)은 파라미터 이름을 나중에 바꿔도 호출자가 안 깨지게 합니다.

> 💡 핵심: `/` 앞은 위치만, `*` 뒤는 이름만.

## Part 5. 고차 함수와 데코레이터 맛보기

### 5-1. functools.partial

인자 일부를 미리 채운 새 함수를 만듭니다.
콜백에 추가 인자를 넘겨야 할 때 클로저 대신 씁니다.

```python
from functools import partial

def greet(greeting, name):
    return f"{greeting}, {name}"

hi = partial(greet, "Hi")
print(hi("dh"))
# Hi, dh
```

**JS에서는:** `greet.bind(null, "Hi")`.

> 💡 핵심: partial = bind의 인자 고정 기능.

### 5-2. 데코레이터는 클로저다

데코레이터는 "함수를 받아 감싼 함수를 돌려주는 함수"입니다.
`@trace`는 `add = trace(add)`의 문법 설탕일 뿐입니다.
Django의 `@login_required`가 정확히 이 구조입니다. (본격은 Day 7)

```python
from functools import wraps

def trace(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        print("call", fn.__name__)
        return fn(*args, **kwargs)
    return wrapper
```

```python
@trace
def add(a, b):
    return a + b

add(1, 2)
# call add
```

`*args, **kwargs`로 받아 그대로 넘기면 **어떤 시그니처든** 감쌀 수 있습니다.
`@wraps`는 원래 함수 이름·docstring을 보존합니다.

**JS에서는:** `const traced = (...a) => { log(); return fn(...a); }`.
TS 데코레이터와 비슷하지만 Python 쪽이 훨씬 일상적입니다.

> 💡 핵심: 데코레이터 = 고차 함수 + 클로저 + `*args/**kwargs`.

## Part 6. CS 심화: 콜 스택

### 6-1. 스택 프레임(활성화 레코드)

함수를 호출할 때마다 **스택 프레임**이 하나 쌓입니다.
프레임에는 로컬 변수, 인자, 돌아갈 위치, 계산 중인 임시값이 들어 있습니다.
함수가 return하면 프레임이 pop됩니다.

```text
main
 └─ outer()   frame: k
     └─ mul() frame: x, (cell→k)
```

CPython 프레임은 C 스택이 아닌 **힙의 프레임 객체**지만
(3.11+는 더 가벼운 내부 구조), 개념은 똑같이 LIFO 스택입니다.

> 💡 핵심: 호출 = push, return = pop.

### 6-2. 재귀 한도와 TCO 부재

재귀가 깊어지면 프레임이 계속 쌓입니다. CPython은
기본 약 1000단계에서 `RecursionError`로 막습니다.
그리고 Python은 **꼬리 호출 최적화(TCO)를 하지 않습니다**.

```python
import sys
print(sys.getrecursionlimit())
# 1000
```

한도를 올리는 건 임시방편입니다(진짜 C 스택이 넘치면 크래시).
깊은 재귀는 **반복문이나 명시적 스택**으로 바꿉니다.

**JS에서는:** 엔진마다 한도가 다르고 `RangeError: Maximum call
stack size exceeded`. 표준엔 TCO가 있지만 V8은 구현하지 않습니다.

> 💡 핵심: Python에서 깊은 재귀는 피하고 반복으로.

## 연습문제

### 문제 1. make_adder

클로저로 `make_adder(n)`을 작성하고, `add5(3) == 8`을 확인하세요.
`__closure__`로 셀에 저장된 값을 출력하세요.

<details>
<summary>정답 보기</summary>

```python
def make_adder(n):
    def add(x):
        return x + n
    return add

add5 = make_adder(5)
assert add5(3) == 8
```

```python
cell = add5.__closure__[0]
print(cell.cell_contents)
# 5
print(add5.__code__.co_freevars)
# ('n',)
```

**설명**

- `add`가 바깥 변수 `n`을 참조하므로 `n`은 **free variable**이 되고,
  CPython은 이를 cell 객체에 담아 힙에 보관합니다.
- `co_freevars`는 그 함수가 바깥에서 가져다 쓰는 이름 목록입니다.
- `make_adder`가 반환된 뒤에도 셀이 살아 있어 `n`을 계속 씁니다.

</details>

### 문제 2. 루프 람다 고치기

아래가 `[0, 1, 2]`를 출력하도록 고치세요.

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)
print([f() for f in funcs])
```

<details>
<summary>정답 보기</summary>

현재 출력은 `[2, 2, 2]`입니다. 세 람다가 모두
**같은 변수 `i`** 를 참조하고, 호출 시점에 `i`는 2이기 때문입니다.

**수정 1: 기본 인자로 값 고정**

```python
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)
```

**수정 2: 팩토리 함수로 새 스코프 만들기**

```python
def make(i):
    return lambda: i

funcs = [make(i) for i in range(3)]
```

**설명:** 수정 1은 기본값이 **정의 시점**에 평가되는 성질을,
수정 2는 호출마다 **새 스코프(새 셀)** 가 생기는 성질을 이용합니다.
`functools.partial(lambda i: i, i)`도 같은 효과입니다.

</details>

### 문제 3. 위치 전용·키워드 전용

`def f(a, /, b, *, c): ...`에 대해 올바른 호출 2개,
잘못된 호출 2개를 쓰고 각각 이유를 설명하세요.

<details>
<summary>정답 보기</summary>

```python
def f(a, /, b, *, c):
    return (a, b, c)

f(1, 2, c=3)
f(1, b=2, c=3)
```

둘 다 OK: `a`는 위치로, `b`는 위치/이름 모두 가능, `c`는 이름으로.

```python
f(a=1, b=2, c=3)
# TypeError: a는 위치 전용
f(1, 2, 3)
# TypeError: c는 키워드 전용
```

**설명:** `/` 왼쪽은 이름으로 못 넘기고, `*` 오른쪽은
이름으로만 넘깁니다. 내장 함수 `len(obj)`이 위치 전용,
`sorted(xs, key=..., reverse=...)`의 옵션이 키워드 전용인 예입니다.

</details>

### 문제 4. sum_all

`sum_all(*nums, start=0)`을 구현하세요.
`sum_all(1, 2, 3, start=10) == 16`이어야 합니다.

<details>
<summary>정답 보기</summary>

```python
def sum_all(*nums, start=0):
    total = start
    for n in nums:
        total += n
    return total

assert sum_all(1, 2, 3, start=10) == 16
assert sum_all() == 0
```

또는 간단히:

```python
def sum_all(*nums, start=0):
    return start + sum(nums)
```

**설명**

- `*nums` 뒤에 오는 `start`는 **자동으로 키워드 전용**입니다.
  위치 인자는 전부 `*nums`가 먹어 버리기 때문입니다.
- 그래서 `sum_all(1, 2, 10)`은 start가 아니라
  nums=(1, 2, 10)으로 해석됩니다.
- `nums`는 튜플이므로 수정이 필요하면 `list(nums)`.

</details>

### 문제 5. (심화) 재귀 → 반복

재귀 팩토리얼을 작성한 뒤, `setrecursionlimit` 없이
n=2000에서도 동작하도록 **반복**으로 바꾸세요.
콜 스택 관점에서 왜 안전한지 설명하세요.

<details>
<summary>정답 보기</summary>

**재귀 버전 (n=2000에서 실패)**

```python
def fact_rec(n):
    if n <= 1:
        return 1
    return n * fact_rec(n - 1)

fact_rec(2000)
# RecursionError
```

**반복 버전**

```python
def fact(n):
    result = 1
    for k in range(2, n + 1):
        result *= k
    return result

print(fact(2000).bit_length())
# 19053 (비트 수)
```

참고: `str(fact(2000))`은 3.11+에서 `ValueError`가 납니다.
4300자리 초과 int→str 변환은 DoS 방지로 막혀 있습니다
(`sys.set_int_max_str_digits`로 조정).

**설명**

- 재귀는 호출마다 프레임이 쌓여 깊이 n → 스택 O(n).
  기본 한도 ~1000을 넘으면 `RecursionError`.
- `return n * fact_rec(n-1)`은 곱셈이 남아 있어 꼬리 호출도
  아니고, 애초에 Python은 TCO를 안 합니다.
- 반복은 프레임 하나에서 변수만 갱신 → 스택 O(1).
- 결과가 거대해도 int가 임의 정밀도라 정확합니다(Day 1).
- 실무에선 `math.factorial(n)`(C 구현)을 씁니다.

</details>

## 면접 질문

<details>
<summary>Q1. LEGB와 global/nonlocal의 차이를 설명해 보세요.</summary>

**정의:** 이름은 Local → Enclosing → Global → Built-in 순으로 찾습니다.

**핵심 규칙:** 함수 안에서 이름에 **대입**하면 컴파일 시점에
그 이름은 로컬로 결정됩니다. 그래서 바깥 변수를 재할당하려면
선언이 필요합니다.

- `global x`: 모듈 최상위의 `x`에 바인딩
- `nonlocal x`: 가장 가까운 **감싼 함수**의 `x`에 바인딩
  (전역까지 건너뛰지 않음, 없으면 SyntaxError)

**실무:** `global`은 숨은 상태라 테스트·동시성을 해칩니다.
상태가 필요하면 클로저(`nonlocal`)나 클래스를 씁니다.

</details>

<details>
<summary>Q2. 클로저란 무엇이고, 바깥 함수가 끝난 뒤에도 값이 남는 이유는?</summary>

**정의:** 내부 함수가 감싼 함수의 변수(free variable)를 참조할 때,
그 함수 객체와 참조 변수 묶음을 클로저라 합니다.

**원리:** 바깥 함수의 프레임은 return 시 사라지지만,
CPython은 free variable을 **cell 객체**로 만들어 힙에 둡니다.
내부 함수의 `__closure__`가 셀을 참조하므로, 함수가 살아 있는 한
셀도 GC되지 않습니다.

**함정:** 셀은 값이 아니라 변수를 담으므로 late binding이 생깁니다.
루프 람다가 모두 마지막 값을 보는 이유입니다.

**실무:** 데코레이터, 미들웨어 팩토리, 설정 고정 함수가 모두 클로저입니다.

</details>

<details>
<summary>Q3. *args/**kwargs와 JS rest/spread를 비교하고, 위치 전용(/)을 쓰는 이유를 말해 보세요.</summary>

**비교**

- `*args`: 남는 위치 인자를 **튜플**로 모음 ≈ JS `...args`(배열)
- `**kwargs`: 남는 키워드 인자를 **dict**로 모음.
  JS엔 키워드 인자가 없어 옵션 객체로 대체
- 호출부의 `*seq`, `**mapping`은 JS spread처럼 펼침

**위치 전용(`/`) 이유**

- 파라미터 이름이 공개 API가 되지 않아, 나중에 이름을 바꿔도
  호출자가 깨지지 않습니다.
- `len(obj)`처럼 이름이 의미 없는 인자에 적합합니다.
- `**kwargs`와 이름 충돌을 피할 수 있습니다
  (예: `def f(name, /, **kw)`는 `f("a", name="b")` 허용).

</details>
